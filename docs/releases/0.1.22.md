Rexume now has a skill for agents that start other coding agents in Rex panes and collect their results through Rexume tasks. `rexume install` writes its stub to `~/.claude/skills/rexume` for Claude Code and to `~/.agents/skills/rexume` for Codex and Pi, each when that runtime is set up. The stub has the agent run `rexume skill show`, which prints the guide built into the installed version, with topics for working with other agents, for what differs between Claude Code, Codex, and Pi, and for the task commands. An upgrade keeps an existing stub current but does not create one, so run `rexume install` again to get it. Install leaves a `rexume` skill it did not write as it is, and when `~/.claude/skills` links to `~/.agents/skills` it writes the one file once. `rexume skill status` prints the Rex version and guide hash that the guide was last reviewed against, for a check that compares them with the Rex you run. [The command reference](https://github.com/Entwining/rexume/blob/v0.1.22/docs/cli.md#skill) describes both commands. Install now writes through a symbolic link to a file that does not exist yet, creating that file, where it used to replace the link.

A launcher that chooses Claude Code's provider or account itself, such as a `claude` script that takes a flag for one call and otherwise uses a saved default, can now declare the command it runs: it exports `REXUME_LAUNCH_PID`, the process that becomes Claude Code, and `REXUME_LAUNCH`, that command as a JSON array of strings. A Claude Code conversation started through it reopens with that command in place of `claude`. Before, it reopened as plain `claude`, so the launcher chose its current default and the conversation could come back with another provider or account than it started with. A declaration that cannot be run, such as an empty command, leaves the pane at its shell, with the reason in the daemon's log. [The command reference](https://github.com/Entwining/rexume/blob/v0.1.22/docs/cli.md#a-launchers-command) describes the declaration.
