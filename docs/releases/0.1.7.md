After the Rex server restarts, each pane comes back as it was last used. A pane whose own program had exited comes back exited with the same status, and the program does not run again. A pane whose own program was a Claude Code, Codex, or Pi conversation, such as a finished `codex exec` run, reopens that conversation without a new turn. A pane that is not reopened gets a login shell in its directory, where it used to get a shell with the reopen command typed at its prompt.

Two fixes concern task workers:

- A non-interactive worker that the server's stop cut off ends as `terminated` when the next server starts. It used to stay `running` until its pane was closed.
- A released non-interactive worker's pane closes when the server reports the run's exit late, as it can after `codex exec` prints just before it exits. It used to be kept with "another program ran in the worker's pane after its result".

The state database moves to schema version 3, which earlier versions of rexume refuse to open.
