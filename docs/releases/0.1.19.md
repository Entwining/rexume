When the Rex server takes a second or longer to answer one of the daemon's calls, the daemon's log (`~/Library/Logs/rexume.log` on macOS, `journalctl --user -u rexume` on Linux) now records it as a warning, with the call and how many milliseconds it took. The daemon makes one call at a time, so a call the server holds delays every restore behind it; when restoring takes far longer than usual, this line shows whether it waited on the server. Rex server build `e6592f7` sometimes holds a call to a just-restored session for about 10 seconds; Rex's developers attribute it to a server deadlock fixed after that build. `RUST_LOG=rexume=debug` still logs every call, now with its duration.
