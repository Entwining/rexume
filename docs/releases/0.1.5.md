`rexume task` now takes each turn a worker finishes exactly once and in order, so an orchestrator no longer loses a worker's final report, takes the same answer twice, or collects an answer under the wrong prompt. A round started by `task next` takes the earliest finished turn no round has taken, one started by `task send` takes the turn that took its request in, and the daemon records that turn in the same transaction as the result and the notice, so a daemon or server restart takes nothing twice.

The task commands change, and scripts and agent instructions that drive them need updating:

- `task send ID --message-file PATH` (or `--message TEXT`) gives the worker its next prompt. The daemon delivers it to the worker's conversation once the worker is idle, without typing into the pane, and the round's result is the turn that answers it. `task show` reports the request's delivery state.
- `task next ID` takes the worker's next finished turn without prompting it, such as the final report after an interim one, including a turn that finished before the command.
- `task release ID` ends the task, and only a released task's pane is closed. It refuses while the worker has finished turns no round took, which `task show` counts as `unread`. `task ack` now only marks a result read.
- `task rearm` is removed.

A restored Claude Code conversation reopens in the permission mode its record last shows, including bypass mode, which Claude Code's own resume does not bring back.

The state database upgrades in place the first time the new version opens it. Each existing task keeps the worker conversation and position of its latest round, and one whose latest round had no conversation yet follows the next conversation to report from its pane; a task registered with `--keep-pane` whose result you acknowledged stays open for `task send` and `task next`, while one without it counts as released, as its acknowledgement did before. An earlier version cannot open the upgraded database.
