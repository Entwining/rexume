Rexume now keeps the history of the workflows it ran, so you can judge afterwards how one went: which workers ran, how many rounds each took, what blocked them, and what each changed. The daemon used to delete a task with its rounds, requests, and notices 30 days after it finished, and old restores and epochs the same way; it now archives each of them as it removes it. `rexume export` prints every task, restore, and epoch, in use or archived, as JSON Lines, starting with a header that names the database and ending with a count, so a reader can reject an output that was cut. A blocked round records each time it blocked, with what Rex reported the worker was waiting on and how it ended; notices and requests record how many times they were sent and when the recipient's own record showed them received; and `task add` takes a label for the task from `REXUME_TASK_META`, a JSON object of at most 1 KiB that only `export` prints. [The command reference](https://github.com/Entwining/rexume/blob/v0.1.23/docs/cli.md#export) describes the output.

A task now records the Git working tree its worker's program stood in at `task add`, and each round records that tree before and after the round, as the tree `git add -A` would stage there, without writing anything in the repository. The round's `before` is taken by the command that starts it and its `after` by your first task command after it finished; `rexume task show` shows both with the directory that holds their objects, and `export` carries them. A snapshot that cannot be taken leaves the round as it is and says why: it is limited to 10,000 changed files, 64 MiB, and 5 seconds, every task's snapshots together to 1 GiB of the state directory, and a file that needs a clean filter other than Git LFS's, such as git-crypt's, is snapshotted only on macOS, where Rexume can deny that filter writes to the repository. [The command reference](https://github.com/Entwining/rexume/blob/v0.1.23/docs/cli.md#snapshots) shows how to compare two snapshots and lists every reason one is not taken.

Rexume now follows a worker in a pane no window shows, and the skill starts a worker nobody needs to watch in such a pane. Before, the daemon recorded that worker as closed whenever it started, and a restore did not reopen its conversation. `task add` refuses a worker on another machine, since Rexume follows a worker through this machine's files and processes.

The skill now starts every program it launches for a task without `REX_SESSION`. With Rex's Let agents name sessions setting on, Rex tells an agent started with that variable to name the session after the agent's own task, so a worker renamed the orchestrator's session.

A released worker's pane was sometimes kept open with the note "another program ran in the worker's pane after its result" when nothing else had run there, because Rex reports a pane again when the same program changes directory or a client starts showing the terminal. Rexume now keeps the pane only when another process took the foreground. A round that finished before the upgrade closes its pane only if Rex has not reported the pane since. A run whose round `task abandon` ended while the run still ran keeps its released pane with the note that the pane does not show the run's exit; it used to say that the pane was restored.

`task send` now takes a message of at most 127 KiB instead of 256 KiB. A Codex worker receives the message as one command-line argument, which Linux limits to 128 KiB, so a larger message to a Codex worker on Linux was accepted and never delivered.

The state database moves to schema version 10, which earlier versions of Rexume refuse to open.
