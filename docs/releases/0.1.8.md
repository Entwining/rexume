A task whose worker resumes an earlier conversation now takes the worker's new answer as its first result. It used to take the conversation's first turn, and `task release` then refused until `task next` had taken each earlier turn. A conversation forked in Claude Code is still read from its start.

A conversation record that cannot be read now affects only what reads it. It used to hold back every other task, notice, and request in the daemon, and the whole restore of the session:

- An interactive task's round fails with the read error as its note; `task next` takes the later turns once the record can be read again.
- A released worker whose record cannot be read comes back on the next server instead of being retired.
- A pane whose record cannot be read reopens its conversation without continuing a turn.

A conversation reported on an earlier server no longer stands for what a restored pane runs. A released worker's pane that came back as a shell is restored and kept, where it could be left out of the next restore or closed, and a task, request, or notice waits for its recipient to report on the new server.

The README in the Linux archives links to the documentation of its own release instead of to files the archive does not contain.

The state database moves to schema version 4, which earlier versions of rexume refuse to open.
