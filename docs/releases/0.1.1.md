A session an agent runs inside its own process no longer replaces the pane's conversation. When Codex sends approvals to auto-review, its guardian reviewer starts a few seconds after each conversation and took the pane over, so a restore would reopen a conversation Codex keeps no record of, and a task registered on the pane followed the reviewer instead of the worker. Codex marks its interactive conversations with a record and Pi with its terminal interface, so rexume now ignores an unmarked start from the process that already holds the pane, and, as before, every Claude Code subagent and in-process teammate. An unmarked start from a new process, such as an ephemeral `codex exec` or a `pi -p` run, still takes the pane, so task commands there name it, and a restore starts a shell for it because neither runtime can reopen it.

`install` and `daemon` now refuse `--theme-foreground` and `--theme-background` values not written as `#rrggbb` in hex digits of either case, with a usage error and exit status 2, instead of passing them on to the LaunchAgent.

`brew upgrade rexume` replaces the program, and the running daemon restarts on the new one by itself. A Codex conversation already running when you upgrade records itself again only when it next starts or resumes, so restart one whose pane 0.1.0 handed to the reviewer.
