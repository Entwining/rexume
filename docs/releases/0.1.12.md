Rexume now reopens conversations in the panes Rex restores itself. After the Rex server stops, Rex brings each session back with a new login shell in every pane; in a pane that ran a Claude Code, Codex, or Pi conversation, Rexume types a short `rexume gate` line into that shell once it shows an empty prompt, and the conversation reopens there: once with a prompt to continue when the server's end cut off its turn, otherwise without a new turn. It runs through your shell, so your alias or function for the agent's command applies. Rexume types nothing into a pane where you started typing, whose prompt does not end in a space, or where another program runs, and leaves it to you after 30 seconds.

This needs a Rex that restores its own sessions: the Rex app 0.1.0-preview.23 or later on macOS, or the Rex server 0.1.0-preview.11 or later on Linux. Rexume no longer creates sessions or saves layouts, and with them the restore states `sent`, `created`, and `partial` are gone. `rexume status` moves to version 2: each restore is now one pane, with a new `pane` field, in the state `planned`, `typed`, `unknown`, `skipped`, or `failed`.

A released disposable worker's pane that Rex restores is closed once it shows its shell, instead of staying open.

`--theme-foreground` and `--theme-background` are ignored with a warning, since Rexume starts no terminals any more; run `rexume install` again to drop them from the job.

The state database moves to schema version 7, which earlier versions of Rexume refuse to open.
