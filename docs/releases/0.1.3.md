`rexume install` no longer leaves the daemon stopped when it reloads a running job, as it does after a theme change, a different `PATH`, or the `install` that 0.1.2 asked for. `launchctl bootout` returns before the daemon has exited and launchd keeps the job loaded until then, so the `bootstrap` that followed failed with `Bootstrap failed: 5: Input/output error` and left nothing loaded. Install now waits for the daemon to exit before loading the new plist, and writes the plist only once the old job is gone, so a reload that fails anyway is finished by the next `install` instead of being reported `unchanged`. `uninstall` likewise returns once the daemon has exited.

If an earlier `install` failed this way, run `rexume install` again. `brew upgrade rexume` replaces the program, and the running daemon restarts on the new one by itself.
