An interactive worker waiting on a question or permission dialog for one second now notifies its task owner. The blocked notice needs no `task ack`. `rexume task wait` can return on that notice with exit code 3 instead of waiting for the round to finish or time out. A script that treats any non-zero exit as a failure or timeout now also sees 3 for a blocked worker; update it to handle that case separately. Timeout remains 124, and a finished round still exits 0, even when the round failed.

Use `rexume task abandon ID` to stop waiting for an unfinished round without stopping the worker or closing its pane. The round ends as `abandoned` and is acknowledged at once, so no finished notice is sent for it and a running `task wait` returns with exit code 0. A pending request is never sent; one already sent is not withdrawn. The task stays open: take a turn the worker finishes later with `task next` before `task release` will allow release, or send the worker a new request with `task send`.

After a Rex server restart, a restored Codex conversation that was the pane's own program can receive task requests and notices before its first turn, without someone first typing into the pane.

Notices now go to each task owner one at a time, oldest first, while the owner is between turns. Notices still waiting in rexume can be dropped by `task wait`, `task ack`, or `task release` before they enter the runtime's queue. The cost is that a Claude Code owner takes one turn per notice.

The state database moves to schema version 5, which earlier versions of rexume refuse to open.
