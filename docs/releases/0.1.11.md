On a Rex server that restores its own sessions, as the Rex app's server always does, Rexume no longer restores a second copy of each session. It takes the sessions Rex brought back as the ones it saved, goes on recording them, and forgets one you close. Rex restores every pane with a new shell, so in those sessions Rexume reopens no conversation, continues no turn, and shows no earlier exit; the daemon's log names each pane it would have started otherwise, with the conversation to reopen there. A worker task's round left unfinished in such a pane ends as `terminated`, and its owner gets a notice.

A state database that 0.1.10 left with both copies records again. Until now, every observation of the server after such a restore ended on `UNIQUE constraint failed: live.instance_id, live.lineage`. The copies already open stay until you close them.

`rexume status` has a new field, `epoch_error`: the error that ended the daemon's latest observation of the server, or `null`. Stopping or upgrading the daemon is not an error.

The state database moves to schema version 6, which earlier versions of Rexume refuse to open.
