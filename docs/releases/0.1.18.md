Rexume now reopens omp conversations and carries task results to and from them, as it does for Pi. `rexume install` writes an extension to `~/.omp/agent/extensions/rexume.ts` when `~/.omp/agent` exists; the daemon updates the extension after an upgrade but never creates it, so run `rexume install` once if you use omp. In a Rex pane, the extension reports the pane's omp session, records each of its runs in `~/.local/state/rexume/omp`, and takes notices and requests from `~/.local/state/rexume/omp/inbox`; outside a Rex pane it does nothing. A conversation the server's end cut off continues once with `omp --resume FILE`, with the model and thinking level its session file records; omp takes its approval mode from its launch flags and settings, so one started with `--approval-mode` or `--yolo` reopens in the mode its settings give. An omp profile's agent directory, or one that `PI_CODING_AGENT_DIR` or `PI_CONFIG_DIR` names, gets no extension. [The design's limits](https://github.com/Entwining/rexume/blob/v0.1.18/docs/design.md#limits) list what omp does not tell its extensions.

`install` and `uninstall` report the extension as `omp_extension`, with `omp_extension_note`.
