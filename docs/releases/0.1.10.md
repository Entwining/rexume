A restored Claude Code conversation now starts with the launch flags and provider it was started with, such as `--remote-control`, `--add-dir`, `--mcp-config`, or a Bedrock or Vertex region, instead of with Claude Code's defaults. The session-start hook reads them from the agent process itself, its arguments and the environment it started with, and keeps only the flags and variables that `docs/cli.md` lists under `report`: never the launch prompt, inline JSON settings, endpoint URLs, or credentials. Variables from Claude Code's own settings are left to Claude Code, which applies them again on resume. A conversation that reports no such flags or variables drops the ones saved before; one whose process cannot be read keeps them.

A provider variable your shell exports to every program, such as `AWS_PROFILE` from a shell profile, is saved like one set for a single launch, so a restored conversation keeps the value it was started with until you start it again yourself.

The state database stays at schema version 5.
