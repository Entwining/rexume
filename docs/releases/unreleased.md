Rexume now watches an interactive task's worker between rounds, from `task add` until `task release`. Before, once the orchestrator acknowledged a round, a dialog the worker stopped on, such as a permission prompt or a question, sent no notice, and a turn it finished on its own waited as `unread` in `task show` without telling anyone. Now such a dialog gets a blocked notice whether or not a round is open; with none open, the notice asks the orchestrator to read the pane before answering, since the user may have answered it or be working there. A turn the worker finishes while no round is open gets a notice that says how many turns are unread and that `task next` takes them, and a burst of turns gets one notice. Rounds still start only through `task next` and `task send`, and a finished notice for an interactive task now says that the watching lasts until `task release`.

A blocked episode now belongs to the task instead of a round: a round that finishes leaves it open, a round started during it starts as `blocked` without a second notice, and it ends when the dialog closes, the pane closes, or the task is released. `task show` and `task list` add `worker_blocked`, the worker's open episode, beside the round's `blocked`. A blocked notice is sent before the other notices waiting for the same orchestrator, and its text names the round open when it is sent. An interactive task that is not released and whose pane is open is no longer archived.

`task list` moves to JSON version 2 and `status` to version 3, since a notice's `round` and `round_state` can now be `null`. The state database moves to schema version 12, which earlier versions of Rexume refuse to open.

The daemon no longer puts the token that ties its connection to `rex do` on any command line. `rex do` and `rexume relay` used to take it as an argument, so every process listing showed it, and tools that scan command output for secrets, such as an agent's output filter, withheld or redacted whole listings because of it.

Rexume now supports OpenCode 2.3 and later. `rexume install` writes an OpenCode plugin to `~/.config/opencode/plugins/rexume/tui.ts` when OpenCode's configuration directory exists, and installs the skill stub for OpenCode too; run `rexume install` again to add it to an existing installation. A restored pane that ran OpenCode reopens its session with `opencode --session`, and OpenCode workers and orchestrators get notices and requests like the other runtimes. OpenCode runs its turns in a background service of its own, which goes on with a turn the Rex server's end cut off, so Rexume never sends it the continuation prompt.

The Pi and omp extensions no longer end their agent when watching the inbox fails, as when the process has run out of file descriptors: they warn that they stopped watching instead.
