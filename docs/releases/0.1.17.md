`rexume status` and `rexume task list` now remove a notice from the list when its round no longer needs it: a finished notice once its orchestrator acknowledges the round, and a blocked notice once its episode ends. Previously, a notice stayed listed after acknowledgement if Rexume could not see its receipt, because the orchestrator's Claude Code turn hooks were missing or the notice was sent before 0.1.14 moved receipts to the turn record. The notice keeps its state, since an acknowledgement is not a receipt.

The daemon now deletes a task and its notices once all its rounds have finished and none finished or was acknowledged within the last 30 days, whatever the notices' states. Previously, an unconfirmed notice kept its task forever if the receipt never arrived, as when hooks were removed, Pi exited with the notice in its queue, or a Codex orchestrator was never continued. These tasks also kept their orchestrators' records from being deleted. Deletion runs when the daemon next starts observing the server; a notice that arrives later names a task that `task show` no longer finds.

A send that fails before anything leaves no longer returns a notice or request to `pending` if it became unnecessary during the send: a notice whose round was acknowledged or whose blocked episode ended, or a request whose round ended, becomes `superseded`, just as it would have before the send started.

`rexume status` has a new field, `claude_hooks_missing`, which lists the Claude Code turn hooks (`UserPromptSubmit`, `Stop`, `StopFailure`) missing from `~/.claude/settings.json` while Rexume's `SessionStart` hook is there. Without them no Claude Code turn is recorded, so a Claude Code worker's round does not finish and no notice to a Claude Code orchestrator is confirmed. The daemon adds missing turn hooks only when it starts. If a configuration manager replaces `hooks` in that file, declare all four Rexume hooks in its source.
