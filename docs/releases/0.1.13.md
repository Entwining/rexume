A pane whose shell is still reading its startup files now reopens its conversation at once: Rexume reads from the terminal's mode that the shell has not reached its prompt, types the line, and the terminal holds it for the shell's first prompt. Until now, a startup file that printed text without ending the line, and then kept working without starting another program, kept the pane waiting for 30 seconds. A startup file that reads from the terminal, such as one that asks a question, takes that line instead, and the conversation does not reopen.

At a prompt, what follows the cursor on its row no longer keeps Rexume from typing the line. A prompt with an emoji sequence, such as 👨‍👩‍👧‍👦, and a right-hand prompt no longer keeps the pane waiting until it is skipped. Text after the cursor, such as a right-hand prompt or text you typed and then moved back before, is left to the line, which clears it, or in a vi keymap runs it with the line. A released worker's pane that Rex restored is still kept when text other than a right-hand prompt follows its cursor.
