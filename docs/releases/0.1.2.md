Pi no longer crashes at session start when `rexume report pi` ends before reading the session the extension writes to it. Outside a Rex pane the report returned without reading its input, and in some runs Pi's write met the closed pipe and the unhandled error ended Pi, as in `pi -p` from a plain terminal or a script. The extension now handles errors on the report's input and still warns only on the report's exit status, and the report reads its whole input before anything else.

The fix is in the Pi extension, which only `rexume install` writes: after `brew upgrade rexume`, run `rexume install` again to replace it. The daemon restarts on the new program by itself.
